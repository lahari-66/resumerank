## 10.2 Engineering practices

- **Local testing without AWS.** Every AWS client is replaced by an in-memory fake, so the 49 unit
  tests (scoring, both handlers, the SQS path, the fallbacks, every API route and its validation)
  run in under a second with no account and no cost.
- **End-to-end checks against the deployed system.** A curl smoke test exercises the real API
  (job, pre-signed upload, scoring, negative cases, CORS, recruiter key); the load test exercises
  scaling.
- **Reproducible test data.** The six test resumes are generated by a script from fictional
  profiles, including a scanned image-only PDF.
- **Configuration outside code.** Resource names, the API URL and the recruiter key come from Lambda
  environment variables or gitignored files.
- **Version control.** One shared GitHub repository; each member commits their own work under
  their own identity, with small, descriptive commits and no secrets in history.

## 10.3 Deployment

Resources were created in the AWS Console (the fastest option for a two-day scope). Lambda code is
packaged by `scripts/package_lambda.py` – which also bundles `pypdf` for the processor and the skill
dictionary for the API – and uploaded as zip files. The README lists every step in order, together
with the tear-down order used after evaluation.
