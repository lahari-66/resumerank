How it works

1

Recruiter posts a job

Paste the job description – the required skills are extracted automatically from a 153-skill dictionary with aliases (“JS”, “Amazon Web Services”, “k8s”).

2

Candidate uploads a PDF

The browser gets a 5-minute pre-signed URL and uploads straight into a private S3 bucket. No AWS credentials ever reach the browser; only PDFs up to 5 MB are accepted.

3

The upload is queued

S3 emits an event into an SQS queue. The queue absorbs bursts and Lambda drains it, scaling out automatically; poison messages go to a dead-letter queue.

4

The resume is scored

Text is extracted (Textract OCR where available, otherwise the PDF text layer), skills and experience are found and the score is computed: skills 60 + experience 20 + education 20.

5

Ranked and alerted

The result lands in DynamoDB, the leaderboard updates every 5 s and an SNS email is sent for any score of 75 or more. Every run is logged and charted in CloudWatch.

6

A human decides

The recruiter reviews the breakdown, opens the resume and shortlists or rejects. The score orders the pile – it never rejects anyone automatically.

Built to scale

Load balancing

API Gateway is AWS's managed front door: it spreads every request across a fleet AWS operates, with rate (20 req/s) and burst (50) throttling to protect the backend.

Auto scaling

Lambda starts a new copy of the function for each concurrent message – from 0 to the configured maximum – and back to 0 when idle. DynamoDB on-demand scales reads and writes the same way.

Queue-based load levelling

A burst of uploads waits in SQS instead of overwhelming the processor; failed messages are retried and then parked in a dead-letter queue so nothing is lost.
